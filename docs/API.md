# API

Базовый префикс: `/api/v1` (настраивается через `API_V1_PREFIX`). Формат — JSON. Ошибки API возвращаются в виде `{"error":{"code":"...","message":"..."}}`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/health/live` | Процесс API отвечает |
| GET | `/api/v1/health/ready` | API может выполнить запрос к настроенной БД |
| POST | `/api/v1/auth/register` | Создать пользователя |
| POST | `/api/v1/auth/login` | Получить JWT access token |
| GET | `/api/v1/users/me` | Получить профиль текущего пользователя |
| GET | `/api/v1/users/search?q=...&limit=20` | Найти активных пользователей |
| GET | `/api/v1/chats?limit=50&offset=0` | Список чатов участника |
| POST | `/api/v1/chats/direct` | Создать или получить личный чат |
| POST | `/api/v1/chats/group` | Создать группу |
| GET | `/api/v1/chats/{chat_id}` | Получить чат при наличии доступа |
| PATCH | `/api/v1/chats/{chat_id}/preferences` | Настроить mute для текущего участника |
| GET | `/api/v1/chats/{chat_id}/members` | Список участников |
| POST | `/api/v1/chats/{chat_id}/members` | Добавить участника администратором |
| DELETE | `/api/v1/chats/{chat_id}/members/{user_id}` | Удалить участника администратором |
| GET | `/api/v1/chats/{chat_id}/messages` | История с cursor pagination |
| GET | `/api/v1/chats/{chat_id}/messages/search?q=...` | Поиск в чате |
| POST | `/api/v1/chats/{chat_id}/attachments` | Загрузить файл (до 10 MiB по умолчанию) |
| GET | `/api/v1/attachments/{attachment_id}` | Скачать файл участнику чата |
| WS | `/api/v1/ws` | Авторизованное real-time соединение |

### Регистрация

`POST /api/v1/auth/register` принимает `username`, `email`, `password`, `display_name`; возвращает профиль с `201 Created`. Username/email приводятся к нижнему регистру. Username: 3–32 символа `[a-z0-9_]`; пароль: 12–128 символов; отображаемое имя: 1–80 символов после trim. Повтор username/email возвращает `409`.

### Вход

`POST /api/v1/auth/login` принимает `{"identifier":"username-or-email","password":"..."}`. Успешный ответ: `access_token`, `token_type: "bearer"`, `expires_in` в секундах. Неверная пара учётных данных возвращает общий `401 INVALID_CREDENTIALS`, не раскрывающий наличие аккаунта.

Передавайте токен в `Authorization: Bearer <token>`. `GET /api/v1/users/me` требует токен и возвращает публичные поля пользователя. В ответах никогда не возвращается `password_hash`.

`GET /api/v1/users/search` требует токен, принимает `q` (1–64 символа) и `limit` (1–20). Ищет по username и display name среди активных пользователей, исключает текущего пользователя и не раскрывает email. Поиск ограничен 30 запросами за 60 секунд на пользователя в одном процессе.

### Чаты

Все chat endpoints требуют access token. `GET /chats` принимает `limit` (1–100, default 50) и `offset` (default 0), сортирует по последней активности и возвращает `items` и `next_offset`. Для личного чата элемент списка включает публичную карточку собеседника `peer` (`id`, `username`, `display_name`); для группы `peer` равен `null`. `last_message` содержит последний текст или `null`, если в чате ещё нет сообщений.

`POST /chats/direct` принимает `{"user_id":"<uuid>"}` и идемпотентно возвращает личный чат. Пара пользователей канонизируется и защищена unique constraint в PostgreSQL. Создать переписку с самим собой нельзя.

`POST /chats/group` принимает `{"title":"Team","member_ids":["<uuid>"]}`; текущий пользователь добавляется автоматически и становится `admin`. Название после trim должно быть непустым, запрос должен содержать хотя бы одного другого активного пользователя.

Для просмотра чата/участников нужна membership; скрытый чат возвращает `404`. Только администратор группы может добавлять/удалять участника. Удалить последнего администратора нельзя. Прямые чаты не поддерживают управление участниками. Email участников API не раскрывает.

`PATCH /chats/{chat_id}/preferences` принимает `{"muted":true}` и меняет личный флаг уведомлений текущего участника. `GET /chats` возвращает этот флаг в каждом чате.

### История и поиск сообщений

`GET /chats/{chat_id}/messages` принимает `limit` (1–100, default 50) и `before` (opaque cursor). Результаты идут в хронологическом порядке; cursor продолжает выборку к более старым сообщениям. Запрос доступен только участнику чата.

`GET /chats/{chat_id}/messages/search?q=...` ищет подстроку только в указанном чате участника, принимает `limit` (1–100, default 50). Поиск регистронезависимый, параметризованный и экранирует wildcard-символы.

Элементы истории и поиска содержат `reactions` (`emoji`, `count`, `reacted_by_me`), `attachments`, `mentions`, `reply_to`, `read_by`, `edited` и `deleted_at`. Удаление — мягкое: текст заменяется отметкой, запись остаётся в истории. Редактировать и удалять сообщение может только его автор.

Файл передаётся как raw request body; имя указывается в `X-File-Name`, MIME — в `Content-Type`. Файл сохраняется под случайным именем в `ATTACHMENT_STORAGE_PATH`, привязывается к отправителю и чату, а затем включается в сообщение через `attachment_ids`. До привязки скачать его может только загрузивший пользователь; после отправки — участник чата. Лимит задаётся `ATTACHMENT_MAX_SIZE_BYTES`.

### WebSocket

Соединение устанавливается по `/api/v1/ws`. Если передан `Origin`, он должен входить в `CORS_ORIGINS`. Первым JSON-событием клиент обязан отправить:

```json
{"type":"auth.authenticate","request_id":"<uuid>","payload":{"access_token":"<jwt>"}}
```

Токен передаётся в теле события, не в URL. Успешный вход отвечает `connection.ready`; неверный/просроченный JWT закрывает соединение с кодом `4401`. Сервер ограничивает размер event до 16 KiB, до 5 соединений на пользователя, и отправку до 10 сообщений за 10 секунд (на процесс; настраивается окружением).

Для отправки клиент передаёт `message.send` с `request_id` и payload `chat_id`, `client_message_id`, `content`. Сервер проверяет членство и лимиты, фиксирует сообщение в настроенной БД и после commit отправляет `message.ack` отправителю, затем `message.new` всем подключённым участникам чата. `ack` означает сохранение, не прочтение. Повтор с тем же чатом/текстом безопасно вернёт исходную запись; переиспользование ID с другими данными возвращает `MESSAGE_ID_CONFLICT`.

Для реакции клиент передаёт `reaction.set` с `chat_id`, `message_id`, `emoji` и `active`. Поддерживается набор `👍 ❤️ 😂 😮 😢 🎉 🔥 🙏`. Сервер проверяет членство и принадлежность сообщения чату, сохраняет или снимает реакцию и рассылает `reaction.updated` участникам. Повтор установки одного и того же состояния безопасен.

Прочтение последнего видимого сообщения отправляется как `chat.read` (`chat_id`, `message_id`); сервер сохраняет курсор для участника и рассылает `chat.read.updated`. В `message.send` можно указать `reply_to_message_id`; упоминания распознаются по `@username` и сохраняются, только если пользователь входит в чат. `message.edit` принимает `message_id` и `content`, а `message.delete` — `message_id`; оба события рассылают обновлённое сообщение как `message.updated`.

Ошибки отправляются событием `error` с `request_id` и кодом в payload. Сообщения остаются в истории даже если участник был отключён во время рассылки.
