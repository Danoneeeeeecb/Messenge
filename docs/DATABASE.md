# База данных

Production и CI используют PostgreSQL 16. Для локальной разработки без сервера БД используется SQLite через `aiosqlite`; локальный пример настроек выбирает SQLite, а Compose передаёт PostgreSQL URL. Обе СУБД работают через async SQLAlchemy и общие модели. SQLite упрощает локальный запуск, но не заменяет PostgreSQL-проверки в CI.

На этапе аутентификации добавлена таблица `users`, а Alembic metadata импортирует модель `User`.

| Поле | Тип | Ограничения |
|---|---|---|
| `id` | UUID | Primary key |
| `username` | varchar(32) | Unique, lower-case нормализация на входе |
| `email` | varchar(254) | Unique, lower-case нормализация на входе |
| `password_hash` | varchar(512) | Argon2id hash |
| `display_name` | varchar(80) | Not null |
| `created_at`, `updated_at` | timestamptz | DB default timestamp |
| `is_active` | boolean | Not null, default true |

Регистрация ловит `IntegrityError`, чтобы сохранить корректное поведение при гонке на уникальных username/email. Доменные таблицы добавляются отдельными миграциями с переносимыми типами и ограничениями для SQLite и PostgreSQL.

Миграция `20261011_0002` добавляет:

- `chats`: тип `direct`/`group`, название, создатель, временные метки. Для direct чата хранятся отсортированные `direct_user_low_id`/`direct_user_high_id`; уникальное ограничение не допускает дубль пары на уровне БД. Check constraint требует корректную комбинацию полей для каждого типа.
- `chat_members`: составной PK `(chat_id, user_id)`, роль `admin`/`member`, `joined_at`, `muted`, резервный `last_read_message_id`. Индекс по `user_id` ускоряет получение списка чатов пользователя.

Удаление пользователя блокируется внешними ключами `RESTRICT`; удаление чата каскадно удалило бы только записи членства. В API удаления чата пока нет.

Миграция `20261011_0003` создаёт `messages` с UUID, чатом, отправителем, `client_message_id`, содержимым и серверной временной меткой. Уникальность `(sender_id, client_message_id)` защищает повторную отправку. Check constraint не допускает пустой/пробельный текст и ограничивает 10 000 символов. Индекс `(chat_id, created_at, id)` поддерживает стабильную постраничную историю. Внешние ключи не каскадируют удаление сообщений при удалении чата или пользователя.

Миграция `20261011_0004` создаёт `message_reactions` с ключом `(message_id, user_id, emoji)`. Миграция `20261011_0005` добавляет к сообщениям ссылку на ответ, таблицы `message_mentions` и `message_attachments`, а также индексы. Вложение сначала хранится как отдельный загруженный объект, затем привязывается к сообщению; байты хранятся на диске, метаданные — в БД. `chat_members.muted` и `last_read_message_id` используются для пользовательских настроек уведомлений и курсора прочтения.
