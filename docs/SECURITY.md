# Безопасность

## Реализовано

- Пароли хешируются через pwdlib с Argon2id; исходный пароль не сохраняется и не возвращается.
- JWT access token подписывается HS256 (другие алгоритмы отклоняются настройкой) и содержит `sub`, `iat`, `exp`, `jti`. Срок жизни ограничен конфигурацией.
- Секрет JWT обязателен в окружении и проверяется по минимальной длине; секрет отсутствует в исходниках. `.env.example` содержит только демонстрационный placeholder.
- Недействительный, просроченный токен, отсутствующий пользователь и неактивная учётная запись не дают доступ к `/users/me`.
- Ошибка входа не раскрывает, существует ли username или email.
- Для неизвестного пользователя выполняется проверка по dummy Argon2id hash, уменьшая различие по времени ответа.
- История и поиск сообщений каждый раз проверяют членство пользователя; UUID чата сам по себе не даёт доступа.
- Размер сообщения проверяется схемой и БД, а повтор `client_message_id` с изменённым чатом/текстом возвращает конфликт.
- WebSocket требует JWT до бизнес-событий, не принимает токен в URL, проверяет переданный Origin и закрывает невалидные сессии.
- WebSocket ограничивает event size, число соединений и частоту сообщений на пользователя в пределах процесса.
- Менять или удалять сообщения может только их автор; чтение и реакции доступны только участникам чата.
- Загрузка вложений требует членства в чате, имеет настраиваемый лимит размера и хранит файлы под случайными именами. Выдача файла повторно проверяет доступ; сервер скачивает его как attachment.
- Поиск пользователей требует авторизации, имеет ограничение длины/количества ответов и отдельный лимит запросов.
- Настройки считываются из окружения; `.env` исключён из Git.
- Значения `.env.example` нельзя использовать для реального развёртывания.
- CORS разрешает настроенный список источников, по умолчанию — локальный Vite.
- API readiness не возвращает детали ошибки подключения клиенту; необработанная ошибка остаётся стандартной ошибкой API.
- Compose публикует сервисы только на порты разработческой машины и не настраивает TLS.

## Следующие меры

Для многопроцессного развертывания потребуется общий rate limiter и Pub/Sub, а также проверка, что настройки Origin согласованы с frontend. Refresh-токены и отзыв сессий не входят в MVP: после истечения access token требуется повторный вход. Перед сетевым развёртыванием потребуются TLS и отдельные production-секреты.
